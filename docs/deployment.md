# 部署指南

这一篇讲怎么把 `dsh-web-relay` 配起来。安装插件包本身见仓库根目录的 [README](../README.md)；这里从"插件已装进 profile"开始。

## 前置条件

开始之前，先在中继主机上准备好下面几条。它们是**前置条件而不是待配置项**：中继上没有本插件的任何代码，管理登录属于主机管理员自己的设置，插件不会去改别人的 SSH 认证策略。

| 条件 | 说明 |
| --- | --- |
| 一台有公网地址的中继主机 | 一般是一台 VPS。安全组需要放行你要用的网关端口（默认 `8443`）。 |
| 管理账号能公钥登录 | 插件不做口令登录，也没有"管理口令"这个字段。私钥可以填路径，也可以交给系统的身份解析（`~/.ssh/config`、默认私钥、ssh-agent）。 |
| 该账号能免密 `sudo` | 非 `root` 账号执行 `sudo` 时不提示输入口令。插件只调用 `sudo -n`，需要口令时会立即失败并如实报出，不会挂在那里等你输入。是 `root` 则不需要。 |
| 中继上有 `ss`（iproute2） | 用于转发前预检判断端口是否被占。缺它部署会在第 3 步停下。 |
| 中继上有 `systemctl` 与 sshd 单元 | 用于重载 `sshd` 与 Caddy。 |
| 自动安装 Caddy 时中继是 Debian/Ubuntu | 其他发行版会在第 7 步停下并给出需要你手工执行的命令。 |
| 内网主机上有 `ssh`、`ssh-keygen`、`ssh-keyscan`、`openssl` | 缺任一个会在第 0 步停下并指出缺哪个。 |

另外，中继的**安全组**要放行 `gateway.port`、并限制 `22` 的来源。插件不改防火墙：改错了会把你自己锁在门外。

## 配置步骤

首次配置必须在**运行 `dsh web` 的那台机器本机**完成。原因是 DSH 对非 loopback 页面把设置持久化降级为内存，通过中继打开的远程页面根本写不了设置——这个标签页在远程页面上甚至不会出现。原因详见 [安全设计](security.md#远程页面的功能边界)。

1. 把插件装进 profile，重启 `dsh web`。这次启动**不会**自动部署（「随 DSH 启动自动部署」默认关，记录里也还没有成功过的部署）。
2. 在服务器本机用浏览器打开 `http://127.0.0.1:<dshPort>`。
3. 打开 **设置 ▸ 远程访问**，填入下面四类参数（字段细节见 [配置项](configuration.md)）：

   | 字段 | 填什么 |
   | --- | --- |
   | 中继主机 ▸ 地址 | 中继的 IP 或主机名。要裸的 `host[:port]`，不能带 `https://` 或路径。 |
   | 中继主机 ▸ SSH 端口 / 管理账号 / 管理账号私钥 | 管理连接的登录信息。私钥留空则走系统身份解析。 |
   | 中继主机 ▸ 中继主机密钥指纹 | 可选。填了会逐字校验；留空则首次连接按 TOFU 接受，指纹会打印出来供你核对。 |
   | 公网入口 ▸ 网关端口 / 网关口令 | 公网 HTTPS 端口（默认 `8443`）与你自己定的口令。口令只用于在中继上算出 bcrypt 哈希，明文不会落到中继磁盘。 |
   | 启动 ▸ 随 DSH 启动自动部署 | 可选，默认关。详见下文。 |

4. 点「部署」。终端上会打印一行访问地址，形如 `dsh-web-relay: https://<权威>/`。

表单里的修改只留在浏览器里，点「部署」才会写进设置并触发一遍完整引导。口令字段每次都要求重填——它的值从不回传浏览器，所以页面从来没见过它。

**「随 DSH 启动自动部署」的语义。** 它只是一个请求，打开它要**这次部署成功**才算数：成功后每次启动 `dsh web` 都会自动完整重跑一遍部署（因此也会重算口令哈希与会话密钥，设备下次进入要重输一次口令）。失败的部署会把记录写成失败状态，开关随之失效；再成功一次又自动生效。一次启动最多尝试一次，**失败不重试**。

## 点「部署」之后，插件做了什么

每一次部署都是一遍完整的、幂等的引导。它会用你给的管理账号登录中继，把下面这些事做一遍；已经就绪的步骤会快速跳过。

| 步骤 | 做了什么 | 失败会怎样 |
| --- | --- | --- |
| 0 本地工具检查 | 确认本机有 `ssh`、`ssh-keygen`、`ssh-keyscan`、`openssl` | 停下并指出缺哪个 |
| 1 生成中继密钥对 | 生成一把**只用于隧道**的 ed25519 密钥（私钥 `0600`）。已存在则沿用 | 停下 |
| 2 固定中继主机密钥 | 取中继的主机公钥，写进本机专用的 `known_hosts`，并打印 `SHA256:` 指纹 | 指纹与你填的不符时停下，不建立任何后续连接 |
| 3 管理连接与能力探测 | 用管理账号登录，读系统版本，验证免密 `sudo`，确认有 `ss`、`systemctl` 与 sshd 单元 | 停在这里并报出 `ssh` 原文 |
| 4 创建受限账号 `relay` | 在中继上建一个无有效 shell 的专用账号 | 停下，隧道身份不存在 |
| 5 写 `authorized_keys` | 写入隧道公钥，并限制它只能监听 loopback 上的转发端口 | 停下；中继上原有内容不受影响 |
| 6 写 sshd 片段 | 写一个只针对 `relay` 账号的 `Match` 段，收紧转发能力 | `sshd -t` 不通过就不重载并回滚该文件 |
| 7 安装 Caddy 与 fail2ban | Debian/Ubuntu 上从 Caddy 官方 apt 仓库安装，并启用服务；已有则跳过 | 其他发行版停下并给出需要手工执行的命令 |
| 8 计算网关口令哈希 | 把口令交给中继上的 `caddy hash-password`（只经 stdin），得到 bcrypt 哈希 | 停下，Caddyfile 不更新 |
| 9 写 Caddyfile | 写入带标记的托管块：TLS 站点、网关口令、反向代理、访问日志；校验通过才重载 Caddy。随后写入 Caddy 侧的 fail2ban 规则 | 校验不通过就不重载，公网入口保持旧配置 |
| 10 取回 CA 根证书 | 把中继 CA 的根证书取回本机（`$DSH_HOME/dsh-web-relay/ca/root.crt`），并算出指纹 | 停下；服务仍可用，只是拿不到根证书 |
| 11 注册权威并自检 | 把公网权威注册进 DSH 的 Host/Origin 围栏，并从本机探一次，确认权威真的生效 | 停下，设备打开会 403 |
| 12 拉起隧道 | 起 `ssh -N -R`，把中继的 `127.0.0.1:18080` 接到本机的 `dsh web` 端口 | 停下，公网入口返回"隧道未连接" |
| 13 公网自检 | 经真实公网走一遍首次访问的三跳（TLS、换票、会话 Cookie），并列出中继对外的监听端口 | 记录里标出每一跳观察到的结果 |

第 9 步写入前会先检查中继上已有的 Caddyfile：如果块外已经存在全局选项块、同名片段，或已有站点监听同一个端口，插件会**停下并报出那一行**，让你自己合并，而不是擅自改写别人的配置。

第 9 步还会保留块外的原有内容。发行版自带的 Caddyfile 里通常有一个 `:80` 静态站点，它不在插件的托管块里，因此会继续存在——第 13 步记录的"中继对外监听"就是发现它的方式，处置见 [排障与维护](troubleshooting.md#中继上出现了多余的监听端口)。

## 部署完还要做什么

**装根证书（推荐）。** 中继用 Caddy 内置的本地 CA 为 IP 权威签发证书，所以设备需要信任这个 CA，否则每次访问都要手动点过证书警告——那样 TLS 仍然加密流量，但**没有身份验证**，你无法察觉中间人。

根证书只有公钥材料，可以公开分发。它不经过公网 HTTP：引导第 10 步已经把它取回本机。送到设备的两条路：

- 在**本机**的设置 ▸ 远程访问 状态区点「下载根证书」，得到 `dsh-web-relay-ca.crt`；
- 或者直接取 `$DSH_HOME/dsh-web-relay/ca/root.crt`。

再经本机复制、隔空投送、聊天软件等不依赖 TLS 信任的渠道送到设备。**装之前先核对指纹**：设置页状态区显示的根证书指纹，应与中继上 `data/pki/authorities/dsh-relay/root.crt` 的 SHA256 指纹逐字一致。iOS 上要先安装描述文件，再到 设置 ▸ 通用 ▸ 关于本机 ▸ 证书信任设置 里手动开启完全信任。

**装与不装是有区别的**，详见 [安全设计](security.md#证书与-ca)。

部署到此完成，接下来在设备上打开终端里那一行访问地址即可。日常使用方式见仓库根目录的 [README](../README.md)。

## 重新部署与失败恢复

引导是幂等的：部署失败时已经写下的东西留在当时的状态（托管的文件要么是旧的要么是新的，`sshd` 与 Caddy 只在校验通过后才重载），记录里会留下一张逐步结果表与失败那一步的原文。**再点一次「部署」即可从头重来。**

改任何一个部署参数（地址、端口、账号、口令、开关）都走同一条路：一次写入 + 一遍完整引导，没有"只重做变了的那一半"这种逻辑，也不需要重启 `dsh web`。
