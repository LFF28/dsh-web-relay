# 实现：设计假设与核对方式

这份设计建立在若干条对 DSH、Cordis、OpenSSH 与 Caddy 行为的假设之上。它们**不是**"大概是这样"，而是已经被读过源码或实测确认过、但值得在升级后重新验证的结论。

已经写进对应实现文档的结论（例如中继侧的 Host 透传、会话 Cookie、`handle_errors` 接住合成 502、给 Cookie 补 `Secure`、日志打码）不在这里重复，它们各自的依据见 [relay-host.md](relay-host.md)、[public-entry.md](public-entry.md) 与 [安全设计](../security.md)。

## 假设清单

| 假设 | 若错的后果 | 验证方式 |
| --- | --- | --- |
| 行级 `inject` 与模块级 `inject` 是叠加的 | 覆盖 `connection` 行会丢掉它自己声明的注入，插件启动失败 | 起一个 profile，确认 `connection` fiber 同时看到 `credentials`、`webRuntime`、`webRelay` |
| `!!js` 表达式在该行的注入就绪之后求值 | 覆盖行里的 `ctx.webRelay` 为 `undefined`，权威为空，远程 403 | 同上；断言受信列表非空 |
| 覆盖 `connection` 行不会造成 `/api` 路由重复注册 | 抛出"重复前缀路由"错误 | 同上；起 profile 看是否报重复路由 |
| 运行期改权威可以用 `fiber.update(entry.options.config, true)` 完成 | 要么权威改了不生效（要重启 profile），要么解析出的字面量被写回配置文件、覆盖用户文件 | 改一次网关端口，确认远程入口跟着变，且配置文件未被改写 |
| `ctx.loader.resolve('connection')` 在运行时可用 | 无法定位要重解析的行，只能退回到"要求用户重启" | 在设置页点一次部署触发权威变更，观察是否抛"找不到条目" |
| 长响应（`/api` 上的流式输出）穿过 Caddy 与隧道不被缓冲 | 界面长时间不刷新 | 观察一次流式响应是否逐块到达 |
| 隧道端点在转发限制下只能绑 loopback | 端点暴露在公网且无 TLS —— **严重** | 中继上 `ss -ltnp \| grep 18080` 必须是 `127.0.0.1` |
| 客户端可用的平台模块闭集足够渲染设置页 | 设置页在浏览器里报模块解析失败 | 装好后打开设置 ▸ 远程访问，确认页面出现且可以部署 |
| `ctx.configForms.get(entryId)` 在插件半边可用 | 设置页无数据源，只能退回自建 RPC | 装好后确认表单可写、可以部署 |
| 对象级 `.volatile()` 能承载整棵部署子树 | 要么设置页写不进任何字段，要么 volatile 嵌套被 schema 拒绝 | `Config({ deployment: {…} }).deployment.get()` 返回补齐后的值；`tests/config.test.js` |
| volatile 提交会跑 `internal/config` 瀑布 | 交叉字段校验在设置页写入时被绕过，非法地址会存下去 | 非法地址的提交被拒且运行引用的值不变；`tests/config.test.js` |
| patch 的 `config` 是整体替换而不是深合并 | 把 SSH 压缩写在包自己的 patch 里，会被设置页第一次写部署参数时整段覆盖掉 | 合成 profile 后确认那一行的 `config` 里两处内容同时存在 |
| 记录接口落在 `connection` 的认证围栏之后 | 插件在公网上开出一条绕过认证的状态接口 —— **严重** | 不带凭据请求该路径必须回 401；`tests/record.test.js` 对白名单的断言 |
| 不带 `-p` 的 `ss -ltnH` 能看到别的用户持有的监听端点 | 转发前预检误判端口是否空闲，残留清不掉 | 在中继上以管理账号跑一次，与带提权的 `ss -ltnp` 结果比对 |
| 清掉残留的 sshd 子进程后端口立刻可用 | 预检清完仍绑不上，退避继续空转 | 造一次残留（断开内网主机网络后重启插件，恢复网络再点一次部署），看下一轮预检是否直接成功 |
| 转发失败的两种原因只能从中继 sshd 日志区分 | 把配置错当成端口残留，预检反复空跑 | 临时把转发限制改成别的端口，观察中继日志出现"请求被拒绝" |
| 管理账号的免密 sudo 在非交互调用下成立 | 引导停在提权步骤，sshd 片段与 Caddyfile 都写不下去 | 中继上跑 `sudo -n true; echo $?`，期望 0；再关掉免密验证它确实报需要口令 |
| 连接复用能把引导的十几条短命令收敛到一条 TCP 连接，且不改变每条命令的语义（stdin、退出码、输出） | 复用悄悄改掉引导行为（stdin 只送到第一条、退出码不传播），失败模式更难定位 | 连打 6 条命令，确认只产生 1 个套接字与 1 个 master；远端非零退出必须让本地退出码一致；大脚本经复用通道执行输出完整 |
| 过期的 ControlMaster 套接字文件不会让连接失败 | 一次异常终止留下的死套接字让之后所有远程命令都失败，表现为"插件彻底坏了" | 在套接字路径上放一个假文件后连一次，命令仍须成功 |
| 套接字目录缺失**不会**自动回退，所以必须预先创建 | 目录被清理工具删掉后，所有远程命令一起失败 | `start()` 与每次部署前都补建（`0700`） |
| 套接字路径展开后 ≥108 字节时 `ssh` 拒绝启动，因此需要退回直连 | `$DSH_HOME` 很长时插件**完全不可用**，而不是仅失去复用 | 按展开长度检查；`tests/ssh.test.js` 断言 107 字节通过、108 字节拒绝 |

## 怎么跑这些验证

- 设置页相关的三项（平台模块闭集、`ctx.configForms`、volatile 子树）在打开设置 ▸ 远程访问 时就会暴露。
- 交叉字段校验与记录接口的白名单有单测直接覆盖。
- 前四项在 profile 启动时就会暴露。
- 其余各项需要一台真实 VPS 与一台运行 `dsh web` 的内网主机，按 [bootstrap.md](bootstrap.md) 的步骤顺序走完引导后逐条核对。
