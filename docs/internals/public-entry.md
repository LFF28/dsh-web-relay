# 实现：权威注册、自检与换票点

这一篇覆盖三件互相咬合的事：让 DSH 接受公网权威、在部署时验证它真的生效，以及用户在裸地址上首次访问时的"带路"。

## 为什么需要注册权威

DSH 的 `/api` 在认证之前有一道 Host/Origin 围栏（失败返回 **403**，认证失败返回 **401**）。围栏要求 Host 是 loopback，或者在一个**显式声明的权威列表**里；随后还要求请求不是跨站，以及 Origin（若存在）的 host 与 Host 的 host 相同。

围栏明确不是认证层，它防的是"本地 HTTP API 的混淆代理攻击"（DNS rebinding 与跨站请求）。所以正确的做法不是绕过它，而是把公网权威显式声明进去。

同理，首页与令牌校验要求 Cookie 的权威与请求的权威一致，Cookie 名也由权威派生。权威不声明，即使 Cookie 有效也会走未授权路径。

## 权威从哪来

权威由用户在设置页填的两个字段推出，没有第三个来源：

```
权威 = canonicalAuthority(地址) + ':' + 网关端口
       （地址自带端口时以它为准，网关端口不起作用）
```

规范化在插件自己的 `authority.ts` 里完成，不调用 DSH 的导出——`@deepseek-ai/dsh-client-connection` 并不导出这些助手，因此按 `packages/client/connection/src/api-request-trust.ts` 的语义重新实现了 `parseAuthority`、`explicitPort`、`canonicalAuthority`、`isBareAuthority`、`publicAuthority` 与 `canonicalHostname`。

- 形状校验要求裸的规范 `host[:port]`：不能带 scheme、path、userinfo。**形状非法时这次部署被拒**，界面保留草稿并显示原因，文档不变。
- `canonicalAuthority()` 只在权威确实带端口时保留端口。一条实用规则：**端口不写就等于"任意端口"**，围栏的权威条目没有端口时按 hostname 比较。设计上仍要求显式写出中继入口端口，减少隐式行为。

## 运行期怎么让权威生效

DSH 的连接服务把受信列表存成构造期快照，没有 setter。所以权威变化时，插件**重解析** `connection` 行：

```ts
const entry = ctx.loader.resolve('connection')      // Loader 继承 EntryTree
entry.fiber?.update(entry.options.config, true)
```

- `entry.options.config` 是**未求值**的原始配置，仍带着 `!!js` 表达式；重新求值时按当时的权威取值。
- `noSave = true` 让 loader 的写回监听器跳过，解析出的字面量不会覆盖配置文件里的表达式。
- fiber 重启时 `/api` 路由先注销再注册；已建立的 WebSocket 不受影响。

这个动作不做差异判断：每一次部署都会重新解析一次那一行。

与 LAN 信任的关系：`web-app` 的受信列表在 loopback 绑定时是**空列表**（只有绑 `0.0.0.0` 时才会自动加入 LAN 字面量），所以插件的权威不会被默认值覆盖。插件只读它、不改它——两者在 `connection` 行合并。`dsh web` 的 `--trusted-host` 命令行参数与它是同一份数据，但插件不使用那条路径，因为入口是设置页而不是启动命令行。

## 自检

权威声明错了（端口与 Caddy 不一致、地址写错、安全组没开）时，现象是"设备打开是 403 或 401 或超时"，这对远程操作者最难排查：他没有终端，而 DSH 只回一个状态码。因此每次部署完成后主动探测一遍，把"远端某个未知原因"变成"内网终端里的一行错误"。

```
部署第 11 步之后（异步，不阻塞 apply；启动时的自动部署同理）
  │
  ├─ 探测 ①：对 http://127.0.0.1:<dshPort>/ 发一个请求，Host: <权威>
  │            期望：不是 403（说明权威已被围栏接受）
  │
  ├─ 探测 ②：对 https://<权威>/ 经真实公网路径发一个请求（不带任何 Cookie）
  │            期望：TLS 握手成功；得到 401 或 200
  │
  ├─ 探测 ③：带网关会话 Cookie 与 Accept: text/html 再打一次
  │            期望：200 过渡页（带换票标记头），且 Set-Cookie 里有带 Secure 的 DSH Cookie
  │            （入口关掉时期望 403）
  │
  ├─ 探测 ④：带着 ③ 换来的 DSH Cookie 打第三次
  │            期望：200（权威绑定的 Cookie 被接受）
  │
  └─ 汇总：成功 → 日志一行 "remote access ready: <url>"
           失败 → 日志一段可执行修复建议
```

- 探测 ① 只测"围栏是否接受这个 Host"，因此命中 `/api/` 下任一路径即可；不带 Cookie 时正确的期望是 **401**。**403 就是权威没生效的确定信号**——这是本模块最有价值的断言。
- 探测 ① 直接连 loopback，不过隧道，因此它能把"权威没生效"与"隧道没通"分开——这是两个位置完全不同的故障。
- 探测 ② 会真的走公网。它验证证书链、Caddy 是否在跑、安全组是否开放、以及隧道是否真的把流量送到了。默认开启，可用 `selfCheck.publicProbe: false` 关掉（例如内网主机不能直连公网时）。
- 探测 ③ 与 ④ 走的就是操作者首访的那条路。③ 只认状态码不够——过渡页与界面都是 200——所以它同时认那个换票标记头。**200 而不是 3xx 本身就是断言**（见下节）。这两跳同时盯着三件容易静默失效的事：带路还在、换票还在、给 Cookie 补 `Secure` 还在。
- 会话密钥是 ③ ④ 唯一的凭据：它等价于一次口令通过，因此探测本身不产生口令失败、不喂 fail2ban，也不把口令发到公网。它是公网上唯一的密文凭据，所以**只在根证书已取回、对端身份可校验时才发出去**；否则只做 ①②，结论里注明"未验证裸地址带路"。
- 自检发生在部署之后，**失败不阻止 profile 启动**。远程访问是附加能力，让本地 `dsh web` 因为公网链路问题起不来是不可接受的。失败只写日志与记录。

启动时不部署的那条路（开关关着或上次失败）只跑探测 ① 并打一行结论，其余留在上一次部署的记录里。

### 失败信息里给什么

每种失败给出"症状 → 最可能原因 → 下一步"，而不是打印原始错误：

| 观测 | 结论 | 给出的下一步 |
| --- | --- | --- |
| 探测 ① 返回 403 | 权威没进受信列表 | 打印当前权威与 `connection` 行实际解析出的受信列表，指出差异 |
| 探测 ① 连接被拒 | 隧道没通或端口不对 | 打印隧道状态与本机 DSH 端口 |
| 探测 ② 证书校验失败 | 客户端不信任中继 CA | 输出根证书指纹，并指向把根证书送到设备的方式 |
| 探测 ② 401 但浏览器仍打不开 | 浏览器侧 Cookie 或网关口令 | 指向 [安全设计](../security.md) 的前提清单 |
| 探测 ② 超时 | 安全组 / Caddy 未监听 / 端口不通 | 指向 [relay-host.md](relay-host.md) 的防火墙清单 |
| 探测 ③ 拿到 401 而不是 200 | 中继上的 Caddyfile 还是旧版（没有带路改写） | 重新部署一次 |
| 探测 ③ 回了 3xx | 中继上跑的还是更早的插件版本 | 重新部署一次 |
| 探测 ③ 没有换票标记头 | 这一跳不是插件答的过渡页 | 同上 |
| 探测 ③ 里没有 DSH Cookie | 中继上的 Caddyfile 是旧版 | 重新部署一次 |
| 探测 ③ 的 Cookie 没有 `Secure` | 补 `Secure` 的那一步没生效 | 检查上游片段是否被人改过，重新部署一次 |
| 探测 ④ 不是 200 | 换来的 Cookie 被拒（权威绑定的名字对不上） | 打印换到的 Cookie 名与当前权威，指出差异 |

## 换票点

`/relay/enter` 是"用网关口令换到 DSH 会话"的那一步，也是公网 HTTP 面上唯一属于插件的路由。它以精确路径注册，因此不会与其他路由冲突。

它不接受查询参数，也不要求任何 Cookie。它能这样是因为它**在结构上位于网关口令之后**：中继把没有网关会话 Cookie 的请求先交给口令校验，只有通过才继续代理到内网主机。因此"请求到达了换票点"本身就是"口令正确"的证明，插件不需要再校验一遍，也不持有任何入口凭据。

处理逻辑：

```
1. 本地发起 GET http://127.0.0.1:<dshPort>/?token=<启动令牌>，Host 设为权威
2. 收下这一跳的 303 与它下发的 Set-Cookie
3. 向浏览器回 200 过渡页，原样转发 Set-Cookie，页面自己跳回 /
```

第 3 步回的是 **200 而不是 303**，这是这一跳唯一不直观的地方。DSH 的会话 Cookie 只能挂在一次响应上，而 Safari 不保存 3xx 响应里的 `Set-Cookie`（[WebKit bug 186448](https://bugs.webkit.org/show_bug.cgi?id=186448)，2018 年报出、至今未修）：回 303 时 Safari 每一轮都像新客户端，中继重新带路、换票点又回一个 303，直到它报「发生了太多重定向」。Firefox 与 Chrome 保存 3xx 上的 Cookie，所以这个缺陷只在 iOS 上暴露。200 是普通响应，Cookie 照常入账；页面用一条 `meta refresh` 与一行 `location.replace` 回到干净的 `/`，两者都给是为了脚本被禁时仍然工作。

这一跳带一个 `x-dsh-web-relay-handshake: transition` 响应头。过渡页与界面都是 200，状态码本身不足以区分"换票发生了"与"没有发生"，自检与排查因此认这个头。

第 1 步是关键复用点：启动令牌来自 DSH 公开的 `authenticatedUrl(...)`，它把"本进程当前的启动令牌"拼到给定 URL 上。插件因此**永远不接触签名密钥**，也不需要知道 Cookie 是怎么生成的；那一跳走的是 DSH 自己的令牌校验逻辑。

这一跳必须用 `node:http` 发，不能用 `fetch`：令牌的校验依据是请求的 `Host`，而 `Host` 在 fetch 规范里是禁止修改的头。用 `fetch` 时 Host 会是 loopback 地址，权威对不上，签出的 Cookie 名字与受众都会是错的。

`connection` 服务通过子 fiber 注入获取，不放进顶层注入——那会与 `connection` 行注入 `webRelay` 形成等待环。

### 裸地址如何自动带路

操作者打开的是裸权威，中继在**服务端**把这次没有 DSH 会话 Cookie 的文档导航改写成换票路径：

```
GET /   （无 DSH Cookie，Accept: text/html）→ 内部改写 → GET /relay/enter
GET /relay/enter → 200 过渡页 + Set-Cookie（浏览器在这一跳存下 Cookie）
GET /   （带刚拿到的 Cookie）                → 直通 → 200 界面
```

带路的判据是 `Accept` 带 `text/html` 且 Cookie 里没有 DSH 会话 Cookie。接口调用、页面自己发起的资源请求与 WebSocket 握手都不带这个 `Accept`，它们各自的 401 原样透传。带路不看路径：`/`、`/index.html` 与地址栏里手敲的任何路径都落到同一个换票点。

Cookie 在、但已经失效（换过权威或换过签名密钥）时带路不会发生，上游回 401，中继把它换成一次**可见的**跳转到换票路径——这是唯一一种地址栏里会出现这条路径的情况，走完就回到 `/`。

中间那一跳的页面只有一行文字，它是"Cookie 没入账"的唯一证据。插件按来源地址计 30 秒窗口内的命中次数，超过 5 次就改答一页说明（带 `x-dsh-web-relay-handshake: blocked`），说清"浏览器没保存 Cookie"并给出两个可操作的做法，而不是让任何人继续转圈。这个计数只影响这一页的应答。

### 地址与开关

地址完全由权威决定：`https://<权威>/`。它不含任何秘密，所以可以进收藏夹、进浏览器历史、进设备同步与备份——这些地方泄漏它都不构成凭据泄漏。真正承担身份的是网关口令与 DSH 的权威绑定 Cookie。

这意味着这条路径上**没有任何需要生成、轮换或保管的东西**：没有 key，没有记录字段，没有轮换按钮。

`entry.enabled` 是唯一开关：关掉后换票点不再换票，只回一段说明（403），公网入口因此只能靠已有的 DSH Cookie 进入。它的用途是"临时关掉入口而不停隧道"。关掉时中继侧的带路与跳转不动——它们指向的路径还在，只是不再换票，所以不会打转。

### 失败与滥用

- **不校验自家凭据。** 口令校验、失败计数与封禁全在中继那一层。换票点因此没有可被爆破的秘密，也就不需要进程内的计数与锁定。
- **不记录秘密。** 启动令牌只出现在插件到本机 loopback 的那一次请求里，不进日志、不进响应体、不进浏览器地址栏。
- **关掉时回 403 说明**，路由仍在，因此中继侧的带路与跳转不会变成一次往返。

## 启动横幅

引导、隧道与自检都就绪后，插件向 stdout 打印横幅：

```
dsh-web-relay: https://<权威>/
  根证书指纹 <caFingerprint>
  中继主机密钥 <指纹，或「未固定，见设置页的状态区」>
  Caddy <版本号，或「沿用已有安装」>
```

之所以直接写 stdout，是因为日志需要操作者在终端上直接看到这一行可以复制到设备上的地址。它不含任何秘密，因此没有"何时打印"的策略开关。

## 明确不做

- **不做"探测到 403 就静默改配置"。** 权威变化的唯一来源是用户在设置页上的输入，插件不猜。
- **不改写 Host 来让围栏通过。** 围栏唯一信任的信号是"Host 由浏览器真实给出"。
- **不自动把 `--trusted-host` 加到启动参数里。** 插件不打算把权威变成第二个配置位置。
- **不做登出路径**（清除 Cookie）：浏览器的会话 Cookie 是 `HttpOnly`，插件无法替浏览器清除它；清站点数据即可。
- **不做"记住这台设备"。** 任何按设备免输口令的机制都会把口令重新物化成一条长期凭据。
- **不做第三方登录（OIDC / TOTP）。** 对单用户场景是纯粹的复杂度。
