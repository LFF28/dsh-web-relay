# 配置项

配置分两份，写入者和生命周期都不同：

- **部署参数**：你在设置页里填的值，点「部署」才写下去。
- **行为旋钮**：随包发布，全部带默认值，不改也能跑。

两者都不需要你手工编辑文件。

## 部署参数（设置 ▸ 远程访问）

这些字段写在插件自己的配置里，落盘在 profile 的 `cordis.patch.yml`（权限 `0600`，不是 git 仓库的一部分，见 [插件改动了什么](local-changes.md)）。

### 中继主机

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| 地址 | 字符串 | 空 | 中继的 IP 或主机名。必须是**裸的 `host[:port]`**：不能带 `https://`、不能带路径或用户名。为空时插件只做本地准备，不引导。 |
| SSH 端口 | 数字 | `22` | 管理连接的 SSH 端口。 |
| 管理账号 | 字符串 | `root` | 引导与转发前预检都用它登录。非 `root` 时调用 `sudo`，该账号必须能免密 sudo。 |
| 管理账号私钥 | 字符串 | 空 | 私钥路径。留空则用系统身份解析（`~/.ssh/config`、默认私钥、ssh-agent）。插件只把它拼进 `-i`，不读取、不复制、不改权限。 |
| 中继主机密钥指纹 | 字符串 | 空 | 期望的中继主机公钥指纹，`SHA256:…` 形式。留空时首次连接按 TOFU 接受并把观察到的指纹打印出来；填了就逐字校验，不符会停下。 |

**地址带端口时以你填的端口为准**，否则用下面的网关端口。它和网关端口一起决定公网权威：`<地址>:<端口>`。

### 公网入口

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| 网关端口 | 数字 | `8443` | 公网入口的 HTTPS 端口，也是中继上唯一的 HTTP 端口。安全组需要放行它。 |
| 网关口令 | 密钥 | 空 | 你自己定的口令，设备每次进入时在浏览器口令框里输入。**每次部署都要重填**：它是密钥字段，值从不回传浏览器，页面无法回填。地址非空而口令为空时写入会被拒绝。明文只交给中继上的 `caddy hash-password`（经 stdin），不落中继磁盘，落盘的只有 bcrypt 哈希。 |

浏览器口令弹窗里的**账号名固定填 `me`**，弹窗本身不会提示它。这个账号名不是配置项，也不能改：HTTP Basic 的账号名必填且参与校验，而 Safari 与 Chrome 都不再显示 realm，所以它没有可见的展示位。

### 启动

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| 随 DSH 启动自动部署 | 布尔 | 关 | 只是请求。打开它要**这次部署成功**才算数：成功后每次启动 `dsh web` 都自动完整重跑一遍部署（因此口令哈希与会话密钥会重算，设备下次进入要重输口令）。失败后开关自动失效，无需额外记账。一次启动最多尝试一次，失败不重试。 |

### 两条写入校验

有两个组合会在写入时就被拒绝，而不是存下来之后在运行期出问题：

- **地址形状非法**（带 scheme、路径、用户名或首尾空白）。这类值的表现是"设备打开是 403"，而你手上没有任何线索指向那个多余的字符。
- **填了地址却没有口令**。配不出网关。

失败时界面会保留你的草稿并显示原因，文档不变。

## 行为旋钮（随包发布）

这些值写在包自己的 `cordis.patch.yml` 里，全部带默认值，随包发布、改后要重挂载，属于包作者的范围。列在这里是为了让你知道它们存在。

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `logLabel` | `dsh-web-relay` | 所有日志与启动横幅的前缀 |
| `tunnel.relayPort` | `18080` | 中继上 loopback 反向转发端点的端口。**必须与中继侧的 `permitlisten` 和 Caddy 上游一致**——三处不一致时隧道会"连上了但转发失败" |
| `tunnel.backoffMs` | `[1000, 2000, 5000, 15000, 30000]` | 隧道重连退避序列，用尽后停在最后一项 |
| `tunnel.healthyAfterMs` | `10000` | 子进程存活超过此时长才把退避重置到第一项 |
| `tunnel.graceMs` | `3000` | 拆除时先发 `SIGTERM`，再等这么久才 `SIGKILL` |
| `tunnel.extraOptions` | `{}` | 追加给 `ssh` 的 `-o` 选项。安全与可用性相关的选项（`BatchMode`、`StrictHostKeyChecking`、`ConnectTimeout` 等）不允许被覆盖 |
| `bootstrap.stepTimeoutMs` | `120000` | 单个引导步骤的总超时（涵盖 `apt` 安装） |
| `bootstrap.commandTimeoutMs` | `30000` | 引导里单条远程命令的超时 |
| `bootstrap.connectTimeoutSec` | `10` | `ssh -o ConnectTimeout` |
| `entry.enabled` | `true` | 关掉后换票点只回一段说明，公网入口只能靠已有的会话 Cookie 进入。用途是"临时关掉入口而不停隧道"；中继侧的带路逻辑不变 |
| `selfCheck.publicProbe` | `true` | 部署结束后是否真的去请求一次公网权威。内网主机不能直连公网时可以关掉 |
| `selfCheck.probeTimeoutMs` | `5000` | 自检请求超时 |

插件不假定 `dsh web` 的端口：它读 DSH 实际监听的端口作为隧道目标。

### SSH 压缩

在 profile 补丁里给 `tunnel.extraOptions` 加一项 `Compression: "yes"` 可以打开 SSH 压缩（等价于 `ssh -C`）。要提醒的是，它压的是**本机到中继**那一段；中继上的 sshd 在写进上游端口之前就已经解压，所以**中继到设备**那一段的字节数一个都不减。它不是"手机上点会话就重连"这类问题的解。

## 运行记录

插件自己写一份状态记录，落盘在 `$DSH_HOME/dsh-web-relay/record.json`（`0600`），只读出口是 DSH 共享 API 通道下的一条路径，因此在认证围栏之后。设置页的状态区就是读它。

记录里包含：引导与隧道的状态、已生效的权威、观察到的中继主机密钥指纹、根证书指纹与 PEM、逐步引导结果、最近一次失败、最近一次转发前预检。它由插件维护，不是用户配置，不需要你编辑；完整字段见 [实现记录](internals/architecture.md#运行记录通道)。

其中网关会话 Cookie 的比对值**绝不出网**：给出记录的接口按白名单逐字段构造响应，整个网关一节都被挡在外面。
