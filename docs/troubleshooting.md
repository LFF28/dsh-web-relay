# 排障与维护

从症状出发。每一行给出"先看哪里"，避免在四个位置（内网主机、隧道、中继 `sshd`、中继 Caddy）之间乱猜。

一条通用原则：**403 与 401 的区分是最有用的信号。403 永远是权威问题，401 永远是凭据问题。**

## 先看哪里

| 观测点 | 位置 | 内容 |
| --- | --- | --- |
| 设置页状态区 | 服务器本机浏览器 | 引导与隧道状态、权威、访问地址、CA 指纹、逐步引导结果、最近一次错误、最近一次转发前预检 |
| 启动横幅 | 内网主机 `dsh web` 终端 | 访问地址与 CA 指纹 |
| 隧道日志 | 内网主机 `dsh web` 终端 | `ssh` 进程每次退出的退出码与 stderr 摘要 |
| 引导步骤结果 | 设置页状态区 | 每步完成/失败/未执行与一句话说明；第 13 步另带中继对外的监听清单 |
| 访问日志 | 中继 `/var/log/caddy/dsh-relay-access.log` | JSON 单行；来源 IP、状态码、耗时 |
| fail2ban | 中继 | 依据访问日志里带 `Www-Authenticate` 的口令失败封 IP |
| 隧道端点 | 中继 `ss -ltnp \| grep 18080` | 必须是 `127.0.0.1:18080` |

## 症状定位

### 部署阶段

| 症状 | 最可能的原因 | 先看 |
| --- | --- | --- |
| 状态区显示某一步失败 | 引导停在那一步，后续步骤是"未执行" | 状态区该步的说明；它带着远程命令的原文 |
| 报 `Permission denied (publickey)` | 管理账号的公钥登录没配好，或私钥路径不对 | 中继主机上手工试一次 `ssh -i <私钥> <账号>@<主机>` |
| 报 `sudo: a password is required` | 管理账号需要输入口令才能提权 | 中继上跑 `sudo -n true; echo $?`，期望 `0` |
| 第 3 步报"中继上没有 `ss`" | 中继没装 iproute2 | 中继上 `apt-get install -y iproute2` |
| 第 7 步报只支持 Debian/Ubuntu | 中继是别的发行版 | 按步骤说明里的命令手工装好 Caddy 与 fail2ban，再点一次「部署」 |
| 第 9 步报"块外已有全局选项块 / 同名片段 / 端口冲突" | 中继上已有别的 Caddy 配置 | 按报出的那一行自己合并，或换一个网关端口 |
| 每次部署都停在**不同**的步骤，报连接超时 | 到中继的路径丢包 | 见下文[部署总在不同步骤超时](#部署总在不同步骤超时) |
| 部署报 `ControlPath too long`，或 `unix_listener: cannot bind to path` | 前者是 `$DSH_HOME` 太长，后者是复用套接字目录被清理工具删过 | 前者插件会自动退回直连（功能正常）；后者重启 `dsh web` 或点一次部署即可补建 |

### 访问阶段

| 症状 | 最可能的原因 | 先看 |
| --- | --- | --- |
| 页面加载出 **403** | 权威没进 DSH 的受信列表：中继地址 + 网关端口与 Caddy 站点地址不一致 | 内网启动日志里的权威自检；它直接指出两个值的差异 |
| 页面加载出 **401**，地址栏停在换票路径 | 恢复跳转发生过，但换票没成功 | 内网启动日志的自检；它区分"带路不在了"和"换票失败" |
| 页面加载出 **401**，响应体是 `unauthorized` | 这不是一次文档导航（是接口、资源或 WebSocket），中继按设计原样透传 | 检查请求的 `Accept` 是否带 `text/html` |
| 地址栏里出现过换票路径后回到 `/` | 正常：Cookie 在但已失效，中继用一次可见跳转把浏览器送回换票点 | 不用处理；想少一次跳转就清掉该站点数据再打开访问地址 |
| 页面加载出 **421**，或一片空白 | Host 与权威不匹配（421 是兜底站点接住了；空白说明兜底也没生效） | 核对地址栏里的 `host:port` 与设置页显示的权威是否逐字一致 |
| 设备报证书错误 | 设备未信任中继 CA，或未在"证书信任设置"里开启完全信任 | 从本机复制根证书到设备，与设置页显示的指纹核对，见 [部署指南](deployment.md#部署完还要做什么) |
| 弹出重复的用户名/密码框 | 口令不对，或换过口令后浏览器缓存了旧的 | 账号名一直是 `me`；在设置页重填口令并部署，并清除该站点的浏览器数据。成功后勾一次「记住此密码」 |
| 设备报「发生了太多重定向」 | 浏览器没保存会话 Cookie | 先在中继上重新部署一次；仍转圈时插件会在第 6 次停在说明页，按那一页的提示允许该站点使用 Cookie，或换浏览器 |
| `curl -L` 打开地址时重定向绕个不停 | curl 默认不保存 Cookie，每次都被当成首访 | 加 `-c/-b <文件>` 让 curl 收下 Cookie；浏览器不存在这个问题 |
| 中继返回 502「无法连接内网主机」 | 隧道没起来，或端口不一致 | 内网终端的隧道日志；再查中继的 `permitlisten` 与 Caddy 上游地址 |
| 隧道显示已连接，但公网连不上 | 安全组没放行网关端口，或 Caddy 没在监听 | 中继上的验证清单，见下文 |
| 公网端口直接 `Connection refused`，但中继上 Caddy 在监听、隧道也活着 | 你自己的出口 IP 被 Caddy 侧的 fail2ban 封了（诊断时反复发不带口令的请求也算失败） | `sudo fail2ban-client status caddy-dsh-relay` 看封禁列表，`sudo fail2ban-client set caddy-dsh-relay unbanip <你的 IP>` 解封 |
| 隧道连不上，手动 `ssh` 也连不上中继 | 你的出口 IP 被 sshd 自身的来源惩罚或 fail2ban 的 sshd jail 封了——反复的公钥失败会触发它 | 中继 `sshd -T \| grep -i persource` 确认惩罚是否启用；`fail2ban-client status sshd`。修好公钥后等封禁到期，或把出口 IP 加入豁免列表 |
| 隧道日志反复出现 `remote port forwarding failed` | 端口被残留会话占着，或 `permitlisten` 与插件的中继端口不一致 | 状态区里的"转发前预检"取值（见下）；再查中继 `ss -ltnp \| grep 18080` 与 sshd 日志 |
| 隧道日志出现 `Host key verification failed` | 中继换了主机密钥 | 核对云控制台指纹后清空记录里的主机密钥指纹并重新部署 |
| 页面能开但对话不刷新 | 长连接被中间设备或 `stream_timeout` 切断 | 中继访问日志里该连接的耗时；客户端会自动重连 |

### 已知问题：手机上每点一次会话就"重新连接"

这是**已知的、超出本插件范围的问题**。原因是 DSH 的心跳预算不够用一个会话快照的排空时间：心跳间隔 2000 ms、允许错过 2 次，于是等待 pong 的预算约 4 秒；而一个会话快照约 2.9 MB，在中继到设备那条约 0.35 MB/s 的出口上要排约 8 秒，ping 因此超时，整条连接被拆掉。

真因在 DSH 的心跳参数与快照体积（其中一大部分是与消息正文逐字重复的流式数据）。SSH 压缩与 Caddy 都不是它的解——压缩只作用在本机到中继那条快链路上。要彻底解决得改 DSH 侧参数，超出本插件能改的范围。

### 部署总在不同步骤超时

引导要开十几条短连接（每条一个步骤），而到中继的路径有丢包时，独立握手越多、整轮失败率越高；失败点因此**随机漂移**，这不是某一步有缺陷。

插件已经把管理路径收敛到一条复用的 TCP 连接（`ControlMaster`），正常情况下部署期间 `ss -tn | grep <中继>:22` 只应看到一条。若已复用仍频繁超时，可以 `ping -c 20 <中继地址>` 与同期公共地址对比，判断丢包是否只在这条路径上。

## 只能在本机做的操作

设置页只在服务器本机的 loopback 页面上注册，远程设备上没有这个入口。

| 操作 | 位置 |
| --- | --- |
| 改部署参数、重新部署 | 本机页面 ▸ 设置 ▸ 远程访问 |
| 作废全部 DSH 会话 | 本机，见下文 |
| 改模型设置、导入导出设置 | 本机浏览器打开 `dsh web` |
| 中继侧的任何手工改动 | SSH 到中继主机 |

## 常见变更

### 改配置并重新部署

在设置页改字段、点「部署」。这一次写入会触发中继上一遍完整引导，**不需要重启 `dsh web`**。

手工编辑 profile 补丁里的部署参数与点部署等效，走同一条路径。

失败时配置留在失败的那一份，旧地址因此打不开——重新点一次部署即可，引导是幂等的。

### 换网关口令

在设置页重填口令并点「部署」（这个字段每次部署都必须重填）。插件会重新计算哈希、重置网关会话密钥、重写 Caddyfile 并在校验通过后重载 Caddy。两者一起换是刻意的：只换口令时，已经持有网关会话 Cookie 的设备会继续跳过口令校验。

### 作废全部会话

```
# 内网主机，先停掉 dsh web
# 编辑 $DSH_HOME/.credentials.yaml，删除 client-connection/browser-session 这条记录
# 重新启动 dsh web --profile <你的 profile>
# 再回设置 ▸ 远程访问点一次「部署」，把隧道接回来
```

重启本身**不足以**作废 Cookie——签名密钥是持久化的凭据记录，只有删掉它才会轮换。重启也不会把隧道接回来，所以还要再点一次部署（开着「随 DSH 启动自动部署」时由启动那次完成）。

### 轮换隧道公钥

由引导完成：点一次「部署」重跑引导，已存在的私钥会被跳过、`authorized_keys` 那一行由托管块替换。要换掉钥匙本身，先删掉 `$DSH_HOME/dsh-web-relay/ssh/relay_ed25519` 再部署——会生成新的密钥对，旧公钥随托管块一起消失，不需要单独回收。

### 端口被残留会话占着

主机侧异常中断（断电、休眠、切网）不会给中继发 FIN，中继上处理那次连接的进程会继续占着转发端口。中继的 sshd 片段设置了保活，这种会话最多残留约 45 秒。正常情况下转发前预检会先清掉它。

先看状态区里的"转发前预检"：

| 取值 | 含义 | 处置 |
| --- | --- | --- |
| 端口空闲 | 正常 | 无需动作 |
| 清掉了残留监听 | 刚清掉一个残留 | 无需动作；若反复出现，查中继的保活配置与网络稳定性 |
| 未执行 | 预检没跑成（管理密钥被撤销、`sudo` 需要口令、`ss` 缺失、连接超时） | 修好密钥或免密 sudo，或装 iproute2；隧道本身仍在按退避重试 |
| 被别的进程占用，未动手 | 端口被占，但持有者不是本部署的残留 | **不要盲目杀进程**，先按下面的命令查清来路 |

```sh
# 中继主机
sudo ss -ltnp 'sport = :18080'   # 看持有者；不是本部署的残留就别杀
sudo kill <pid>                  # 确认是本部署的残留后杀掉，端口立即释放
```

清理完成后不需要做别的：隧道会以退避周期重试，下一轮就会成功。

### 换公网地址或网关端口

1. 在设置页改地址或网关端口并点「部署」。
2. 插件重算权威、重注册围栏，并在中继上完整重跑一遍引导（站点地址、证书、转发限制都跟着新值走）。
3. 在设备上更新访问地址。

**换权威会让所有旧 Cookie 立刻失效**，这是设计使然。旧中继上的账号、sshd 片段与 Caddyfile 会原样留着，插件不去清理别人的机器。

### 中继上出现了多余的监听端口

中继上对外只应有一个 HTTP 端口。`ss -ltnp` 里出现在网关端口与 `sshd` 之外的任何监听都要问清来路——多一个能吃 Cookie 的端口就多一条绕开 DSH 会话校验的路。

最常见的那一个是发行版 Caddy 包自带的 `:80` 静态站点：

```
# 中继主机
# 从 /etc/caddy/Caddyfile 里删掉托管块之外的 :80 站点块
caddy validate --config /etc/caddy/Caddyfile && caddy reload --config /etc/caddy/Caddyfile
```

部署第 13 步记录里的"中继对外监听"是发现它们的方式。

### 证书续签

Caddy 用内置签发者自动续签，90 天的有效期留了足够余量，正常情况不需要手工动作。

"客户端不再信任证书"时，通常是根证书被重新生成过（例如换过权威）：重跑引导第 10 步就会更新本机的根证书副本，再把新证书送到设备并核对指纹。

### 卸载后清理中继

移除插件包只影响内网主机。中继上留下的东西要手工删：

```
# 中继主机
# 1. 删掉 authorized_keys 里的托管块（最快收回隧道权限的一步）
rm -f /etc/dsh-web-relay/authorized_keys        # 或删掉引用它的那一行
# 2. 删掉 sshd 片段并重载
rm -f /etc/ssh/sshd_config.d/60-dsh-web-relay.conf
sshd -t && systemctl reload ssh
# 3. 删掉 Caddyfile 里的托管块并重载
caddy validate --config /etc/caddy/Caddyfile && caddy reload --config /etc/caddy/Caddyfile
# 4. 删掉专用账号
userdel -r relay
```

步骤 1 之后隧道会在下一次重连时立刻失败——这是最快的收回方式。本机侧可以删掉 `$DSH_HOME/dsh-web-relay/`。

## 中继侧核对清单

部署完成后，下面这些都应该成立。手工核对时照抄：

```
# 中继主机
ss -ltnp | grep -E '18080|8443'         # 18080 必须是 127.0.0.1
ss -ltnp                                # 对外只应有网关端口与 sshd
sshd -T -C user=relay,host=relay,addr=127.0.0.1 | grep -iE 'gatewayports|permitopen|allowtcpforwarding|permittty'

# 未认证且不是文档导航：期望 401，且响应里没有 set-cookie
curl -sS --cacert <根证书> -D- -o /dev/null https://<权威>/

# 首访：裸地址 + 文档导航的 Accept，未带任何 Cookie
# 期望 200、带换票标记头、两条 Cookie 都带 Secure
curl -sS --cacert <根证书> -u me:<口令> -c <jar> -b <jar> -H 'Accept: text/html' -D- -o /dev/null https://<权威>/

# 带着刚拿到的 Cookie 再取一次：期望 200 界面
curl -sS --cacert <根证书> -u me:<口令> -c <jar> -b <jar> -H 'Accept: text/html' https://<权威>/ | grep -c __DSH_BOOT__

# 隧道未连接：期望一段可读提示，不是空响应
curl -sS --cacert <根证书> -u me:<口令> https://<权威>/
```

三条必查项：

1. **未认证请求不得带 `set-cookie`。** 带上就说明口令校验没有被短路保护，任何人都能领到会话密钥。
2. **首访被带进换票点，且那一跳返回 200。** 拿到 401 说明中继上的 Caddyfile 还是旧版；拿到 3xx 说明中继上跑的是更早的插件版本，重新部署一次即可。
3. **认证成功后每条 `set-cookie` 都要带 `Secure`**，包括 DSH 自己那条。缺它就说明补 `Secure` 的那一步掉了。

再核对一次证书有效期，确认 90 天的覆盖真的生效：

```
openssl s_client -connect <权威> </dev/null 2>/dev/null | openssl x509 -noout -dates
```

## 容量与限额

这些值在单用户场景下都不需要调优；它们的作用是让异常（重连风暴、爆破）有一个已知的上界。

| 项 | 值 |
| --- | --- |
| 隧道子进程 | 1 个（另有 1 个串行的预检子进程） |
| 重连退避上限 | 30 秒 |
| 单个引导步骤上限 | 120 秒 |
| 管理连接的 TCP 连接数 | 1（连接复用） |
| 管理连接 master 空闲上限 | 60 秒 |
| 网关会话 Cookie | 12 小时 |
| fail2ban | 5 次 / 10 分钟 → 封 1 小时 |
| 会话 Cookie | 30 天（DSH 默认） |
| 中继证书有效期 | 90 天（自动续签） |
| 长连接上限 | 24 小时 |
