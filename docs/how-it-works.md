# 工作原理

`dsh-web-relay` 把一台内网主机上的 `dsh web` 交给远程设备使用。核心是一条**由内网主机主动拨出**的 SSH 反向隧道：内网主机不开任何入站端口，公网侧只需要一台跑系统 `sshd` 与 Caddy 的中继主机，中继上不安装本项目的任何代码。

## 拓扑

```
 iPhone / 平板
      │  ① https://<权威>            （唯一的公网入口）
      ▼
 ┌──────────────────────────────────────────────────┐
 │ 中继主机（有公网地址的 VPS）                        │
 │   Caddy :8443   TLS 终止 → 网关口令 → 反向代理      │
 │      │  ② http://127.0.0.1:18080  （Host 原样透传）│
 │   sshd          loopback 上的反向转发端点           │
 └──────────────────────────────────────────────────┘
      ▲
      │  ③ ssh -N -R 127.0.0.1:18080:127.0.0.1:3080   （内网主机主动拨出）
      │
 ┌──────────────────────────────────────────────────┐
 │ 内网 DSH 主机                                      │
 │   dsh web          只监听 127.0.0.1:3080           │
 │   dsh-web-relay    守护 ③ + 设置 ▸ 远程访问 页面    │
 └──────────────────────────────────────────────────┘
```

三条方向性结论：

- **内网主机不开放任何入站端口。** 连接方向永远由内网主机发起，第三方即使知道中继的 IP 也连不到内网主机。
- **浏览器只与中继通信**，永不直连内网主机。
- **中继上的 `127.0.0.1:18080` 只在 loopback。** 能连它的只有同一台机器上的 Caddy，它本身是明文 HTTP，从不对外。

中继对外只暴露 `gateway.port`（默认 `8443`）一个 HTTP 端口；隧道端点与 DSH 都只在 loopback 上。

## 四层身份

任何进到 DSH 界面的人都能在那台机器上执行命令，所以这条链路上叠了四层互相独立的认证，任一层失效都不连带其他层：

| 层 | 位置 | 作用 |
| --- | --- | --- |
| 第一层 TLS 校验 | 中继 | 阻止被动旁听与中间人 |
| 第二层 网关口令 | 中继 (Caddy) | 没有口令到不了内网主机 |
| 第三层 DSH 会话 Cookie | 内网 DSH | 阻止无 Cookie 的 API 调用；换权威即失效 |
| 第四层 Host/Origin 围栏 | 内网 DSH | 阻止跨站请求与 DNS rebinding |

第一、二层在中继主机，第三、四层在内网主机。

DSH 自身的认证是单操作者的：一个启动令牌换一个长期 Cookie，没有多用户、没有吊销列表、没有频率限制。把它直接挂到公网，等于把一个能远程执行命令的界面挂到公网——**第二层因此是必需的，不是可选的加固**。

## 首次访问是怎么走通的

你只需要记住一个地址：`https://<权威>/`。它不含任何秘密，所以可以收藏、同步、备份。

```
浏览器打开 https://<权威>/  （还没有 DSH 会话 Cookie）
  → 中继发现这是一次文档导航，在内部交给换票点
  → 插件在本机完成一次令牌交换，回一页过渡页并把 DSH 会话 Cookie 交给你
  → 浏览器带着 Cookie 重新取 /，进入界面
```

换票这一步发生在中继内部，地址栏里始终只有裸权威。凭据是你在浏览器口令框里输入的那一个网关口令（账号名固定填 `me`，弹窗不会提示它），有效期 12 小时；过期后重新输一次即可。

## 插件坚持的不变量

这些是设计上的硬约束，没有对应的开关：

- DSH 永远只监听 `127.0.0.1`，内网主机永远不监听公网。
- 中继上只有一个 HTTP 端口。Cookie 不按端口隔离（RFC 6265 第 8.5 节），多一个能吃 Cookie 的端口就多一条读到会话 Cookie 的路。
- 访问地址（裸权威）不含任何秘密；网关口令不出现在 URL、书签或浏览器历史里。
- Caddy 永远不改写 `Host` / `Origin` / `Referer`：DSH 的围栏唯一信任的信号是"Host 是浏览器真实给出的"。
- 每个经过中继的 `Set-Cookie` 都被补上 `Secure`（DSH 自己不下发这一位）。
- 中继上的反向转发端点永远只在 loopback。
- 浏览器只与中继通信，永不直连内网主机。
