# 插件改动了什么

这一篇列清 `dsh-web-relay` 在你的机器和中继主机上留下的东西。**它会修改中继主机**——这是它工作的方式，所以值得你事先知道每一处改动的位置与作用。

## 本机（运行 `dsh web` 的机器）

### 插件的数据目录

所有与中继相关的文件都放在一个目录下：`$DSH_HOME/dsh-web-relay/`。

| 路径 | 权限 | 内容 |
| --- | --- | --- |
| `ssh/relay_ed25519` | `0600` | **隧道专用**私钥。由引导第 1 步生成，只用于登录中继上的受限账号 `relay`，与你的管理私钥无关。 |
| `ssh/relay_ed25519.pub` | `0644` | 对应的公钥，写进中继的 `authorized_keys`。 |
| `ssh/known_hosts` | `0600` | 只含中继这一台主机的公钥。刻意不复用 `~/.ssh/known_hosts`：一份只有这一台中继的独立文件才能让"首次连接核对指纹"有一个确定的答案。 |
| `ssh/cm/` | `0700` | 管理连接的复用套接字目录。目录缺失时 `ssh` 会直接失败，所以启动与每次部署前都会补建。 |
| `ca/root.crt` | `0644` | 中继 CA 根证书的副本。只有公钥材料，本来就要装到设备上。 |
| `record.json` | `0600` | 运行记录：状态、权威、指纹、逐步引导结果。插件写、设置页读。 |

### profile 的配置

你在设置页填的部署参数（含**明文网关口令**）落在 profile 的 `cordis.patch.yml` 里，权限 `0600`。这个文件不属于 git 仓库。

明文保存是"用户自填口令"的必然结果，写在这里以免被误认为已加密。可以缓和这一点的是：这个字段的值从不回传浏览器，因此设置页无法显示、也无法回填它；引导时它只经 stdin 交给中继上的 `caddy hash-password`，不出现在命令行参数、日志、记录或临时文件里。

### 不改的东西

- 不修改 DSH 源码，不修改你的 `~/.ssh/config`，不动 `~/.ssh/known_hosts`。
- 不请求你的管理私钥做任何读写：它只被拼进 `-i` 参数。
- 不配置中继的 SSH 登录策略、不改中继的防火墙、不动中继上托管块之外的内容。

## 中继主机

### 新增的账号

一个专用账号 `relay`：无有效 shell（`/usr/sbin/nologin`），只为承载隧道。

用独立账号而不是 `root` 或管理账号，是因为 `authorized_keys` 上的限制作用于**那把钥匙**——专用账号让"隧道这把钥匙能做什么"与"管理钥匙能做什么"彻底分开。

### 写入的四处配置

全部写在带标记的托管块里（`# BEGIN dsh-web-relay` … `# END dsh-web-relay`），**标记之外的内容原样保留**。重新部署时先删旧块再写新块，因此可以反复执行。

| 位置                                                                                          | 内容                                                               | 作用                                                                                         |
| ------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `/home/relay/.ssh/authorized_keys`                                                          | 一行公钥，带 `restrict,port-forwarding,permitlisten="127.0.0.1:18080"` | 把这把钥匙的能力锁死为：在 loopback 上开一个转发监听。不能执行命令、不能连别的端口、不能绑到公网接口。                                   |
| `/etc/ssh/sshd_config.d/60-dsh-web-relay.conf`（无该目录时写主配置的同名块）                               | 一个只针对 `relay` 账号的 `Match` 段                                      | 收紧到只允许反向转发、禁止本地转发与 pty，并设置保活，让异常消失的会话在约 45 秒内被丢弃、释放端口。                                     |
| `/etc/caddy/Caddyfile`                                                                      | 全局选项块 + 一个具名上游片段 + 权威站点 + Host 不匹配的兜底站点                          | 公网入口：TLS 终止、网关口令、反向代理、访问日志。写入前先 `caddy fmt` 与 `caddy validate`，校验通过才 reload；不通过就回滚。        |
| `/etc/fail2ban/filter.d/caddy-dsh-relay.conf` 与 `/etc/fail2ban/jail.d/caddy-dsh-relay.conf` | 网关口令的爆破防护                                                        | 只统计带 `Www-Authenticate` 的口令失败，不把 DSH 自身的 401 计入（否则正常使用会把自己封掉）。这两个文件整体由插件拥有，首行标记不匹配时停下、不覆盖。 |

写入前会检查块外是否已经存在全局选项块、同名片段，或监听同一端口别的站点；命中就停下并报出那一行，让你自己合并。插件不擅自改写别人的全局配置。

`deploy/fail2ban/jail.d/jail-sshd.local` 是**唯一不自动安装**的模板：它的 `ignoreip` 依赖只有你知道的内网出口地址，写错会把隧道一起封掉，所以只作为模板提供。

### 安装的软件包

在 Debian/Ubuntu 上，如果中继上还没有：

- **Caddy**：从 Caddy 官方 apt 仓库安装，并启用服务。走包管理器是为了白拿 systemd 单元、`caddy` 账号与 `/var/lib/caddy` 数据目录——Caddy 的本地 CA 就落在那里。
- **fail2ban**：用发行版包，并启用服务。

两者都是"已经有了就跳过"。其他发行版会在这一步停下并打印需要你手工执行的命令。

### 运行期的一次提权

除了上述写入，插件还会在每次建立隧道**之前**用管理账号连进中继做一次检查：看反向转发端口是否被上一轮的残留会话占着。这是整个设计里唯一一处运行期提权，所以面收得很窄：

1. 先不带特权地问一次端口；空闲就直接结束（常见路径根本不碰 `sudo`）。
2. 只有被占时才提权取持有者，并逐条核对：可执行文件必须是 `sshd` 或 `sshd-session`，且进程属主必须是 `relay`。
3. 两条都成立才发信号清掉它；任何一条不成立就停手并记录原因。

它不新增文件、账号或服务，但确实要求中继上有 `ss`（iproute2）、且管理账号能免密提权——这两条因此是部署的前置条件。预检失败不是致命错误：它是一次修复而不是一道门，失败只记录原因然后照常尝试建立隧道。

### CA 与证书

Caddy 的本地 CA 自己生成并自己续签：私钥与根证书在 `/var/lib/caddy/.local/share/caddy/pki/authorities/dsh-relay/` 下，根证书 10 年、中间证书 1 年、站点证书 90 天。中继上不需要 `openssl`，也不需要 cron。

中继上因此**没有任何 DSH 凭据**：只有 SSH 公钥、TLS 私钥/证书和 Caddyfile。

### 访问日志

`/var/log/caddy/dsh-relay-access.log`，以 `0600` 写入，`roll_size 20MiB`、`roll_keep 5`（Caddy 的默认值是 100MiB × 10 份，对小磁盘的中继太宽松）。日志里 Cookie 与 `Authorization` 默认已打码，查询串里的 `key` 与 `token` 也替换成 `REDACTED` 作为兜底。

## 卸载

```
dsh plugin --profile web remove dsh-web-relay
```

这会移除插件行与浏览器侧的界面，**但不会回滚中继上的任何改动**：`relay` 账号、sshd 片段、Caddyfile 托管块、fail2ban 规则、证书与访问日志都还在。插件不去清理别人的机器。

中继侧的手工清理步骤见 [排障与维护](troubleshooting.md#卸载后清理中继)。最快收回隧道权限的方式是从 `authorized_keys` 删掉那一行——隧道是内网主机主动拨出的，下一次重连就会立刻失败。

本机侧可以删掉 `$DSH_HOME/dsh-web-relay/` 整个目录；profile 的 `cordis.patch.yml` 里那一段部署参数也由你自己决定是否删除。
